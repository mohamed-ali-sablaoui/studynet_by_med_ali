Partie 01

Cours complet — Architecture des ordinateurs

Notions, définitions, tableaux, méthodes de calcul et exemples expliqués.

1.1 — Définitions fondamentales

Un ordinateur est une machine de traitement de l'information : il acquiert des données, les mémorise, les traite puis restitue des résultats. Ces quatre fonctions forment le fil conducteur de toute architecture.

L'informatique est la science du traitement automatique de l'information. Un système informatique associe matériel, logiciels et utilisateurs pour répondre à des besoins. L'architecture décrit les unités fonctionnelles, leurs connexions et leur coopération.

▣

Hardware — matériel

Processeur, carte mère, RAM, stockage, écran, clavier, réseau et autres composants physiques.

▤

Software — logiciel

Programmes exécutés par le matériel. Logiciels de base : système d'exploitation, utilitaires, compilateurs. Applications : navigateur, bureautique, jeux, gestion.

À ne pas confondre : l'ordinateur désigne la machine ; le système informatique est l'ensemble matériel/logiciel organisé pour les utilisateurs.

1.2 — Les couches d'un système informatique

Utilisateur → Applications → Système d'exploitation → Matériel

Chaque couche utilise les services de celle qui se trouve en dessous et masque une partie de sa complexité. Exemple : lors d'un enregistrement, l'utilisateur demande à l'application de sauvegarder ; l'application demande au système d'exploitation d'écrire ; le système pilote le périphérique de stockage.

Le système d'exploitation est donc une couche logicielle essentielle entre les applications et le matériel. Il coordonne les ressources et permet d'utiliser la machine sans commander directement chaque circuit.

La frise historique du support situe notamment la Pascaline (1642), l'algèbre de Boole, les travaux de Shannon, le transistor (1947), le circuit intégré (1958), le microprocesseur Intel 4004 (1971) et le PC IBM (1981). La loi de Moore décrit historiquement le doublement approximatif du nombre de transistors d'une puce sur une période proche de deux ans ; c'est une observation historique, pas une loi physique garantissant l'avenir.

2.1 — Structure générale et périphériques

L'unité centrale comprend l'unité centrale de traitement (UCT/CPU) et la mémoire centrale (MC). Elles communiquent grâce aux bus. Les unités d'entrée/sortie relient la machine au monde extérieur.

Entrée

Envoie des informations vers l'ordinateur : clavier, souris, scanner, webcam, microphone.

Sortie

Restitue les résultats : écran, imprimante, haut-parleurs, vidéoprojecteur.

Entrée / sortie

Échange dans les deux sens : disque, SSD, clé USB, modem, carte réseau, écran tactile.

Un périphérique se classe selon le sens de circulation des informations, pas selon son apparence.

2.2 — Les trois bus

BusRôleSens
Bus d'adressesL'UCT indique quelle case mémoire ou quel périphérique est visé.Généralement UCT → mémoire/E/S.
Bus de donnéesTransporte les instructions et les valeurs lues ou écrites.Bidirectionnel.
Bus de commandeTransporte les signaux : lecture, écriture, validation, synchronisation.Selon le signal.

Le bus d'adresses est généralement unidirectionnel car c'est l'UCT qui sélectionne l'emplacement à accéder. Le bus de données doit circuler dans les deux sens : lecture (mémoire vers UCT) et écriture (UCT vers mémoire).

2.3 — Von Neumann et Harvard

Von Neumann

Programme et données partagent une même mémoire et un chemin de communication commun. Organisation simple, mais les transferts instruction/donnée peuvent se concurrencer.

Harvard

Mémoires et chemins distincts pour instructions et données. Permet des accès séparés, souvent utilisés dans certains microcontrôleurs et processeurs spécialisés.

Dans le modèle de Von Neumann, on retrouve UCT, mémoire centrale, bus et unités d'entrée/sortie. Le programme stocké en mémoire est lu instruction après instruction, puis exécuté par le processeur.

3.1 — Mémoire : notions et caractéristiques

Une mémoire est organisée en cases. Chaque case possède une adresse unique et contient un mot. L'adresse désigne l'emplacement ; le contenu est la donnée stockée.

Temps d'accès

Durée entre le lancement d'une lecture/écriture et son accomplissement.

Temps de cycle

Intervalle minimal entre deux accès successifs ; il est supérieur ou égal au temps d'accès.

Débit

Quantité de données transférées par seconde, généralement en octets/s.

Volatilité

Une mémoire volatile perd son contenu lorsque l'alimentation est coupée.

Hiérarchie des mémoires — de la plus rapide à la plus lente

Registres → Cache → Mémoire centrale → Mémoire d'appui → Mémoire de masse

En descendant dans la hiérarchie, la capacité augmente généralement et le coût par bit diminue, mais le temps d'accès augmente. Les registres sont dans le processeur ; le cache conserve des données/instructions utiles proches du CPU ; la RAM contient les programmes en cours ; SSD/disque assurent le stockage durable.

3.3 — Capacité d'adressage et capacité mémoire

Si le bus d'adresses comporte n fils, chaque fil peut prendre 0 ou 1. Il existe donc 2ⁿ combinaisons d'adresses.

CA = 2ⁿ cases   |   CM = CA × taille d'une case

Si la largeur du bus de données est m bits, une case contient m/8 octets (lorsque m est multiple de 8). Attention : CA compte des cases, CM mesure une quantité de données.

Unités du support : 1 Ko = 2¹⁰ octets = 1 024 octets ; 1 Mo = 2²⁰ octets ; 1 Go = 2³⁰ octets. En terminologie stricte, on écrit Kio/Mio/Gio pour les puissances de 2, et ko/Mo/Go pour les puissances de 10.

Exemple détaillé

n = 8 fils d'adresses et m = 16 bits de données. CA = 2⁸ = 256 cases. Chaque case contient 16/8 = 2 octets. CM = 256 × 2 = 512 octets.

Plus grande adresse

Les adresses commencent à 0. Pour n bits, la plus grande vaut 2ⁿ − 1. En hexadécimal, lorsque n est multiple de 4, elle s'écrit avec n/4 chiffres F : 20 bits donnent FFFFF.

3.4 — Lire et écrire en mémoire

Cycle de lecture

  1. L'UCT place l'adresse sur le bus d'adresses.
  2. Elle sélectionne la mémoire et active la commande de lecture.
  3. La mémoire place le contenu sur le bus de données.
  4. L'UCT récupère la donnée.

Cycle d'écriture

  1. L'UCT place l'adresse à modifier sur le bus d'adresses.
  2. Elle place la donnée sur le bus de données.
  3. Elle sélectionne la mémoire et active la commande d'écriture.
  4. La case mémorise la donnée.

4.1 — L'UCT : unité de commande et UAL

L'UCT (CPU) comprend deux grandes parties complémentaires :

Unité de commande (UC)

Organise et déclenche les opérations. Elle interprète l'instruction et émet les signaux de commande nécessaires.

Unité arithmétique et logique (UAL)

Effectue les opérations arithmétiques et logiques : addition, soustraction, multiplication, ET, OU, NON et comparaisons.

Le jeu d'instructions est l'ensemble des opérations que le processeur sait exécuter. RISC privilégie un ensemble réduit d'instructions simples et souvent de format fixe (ex. ARM, RISC-V). CISC propose un jeu plus riche et des instructions parfois plus complexes/de longueur variable (ex. x86). Ce sont des philosophies de conception, pas une règle absolue de vitesse pour chaque programme.

4.2 — Registres essentiels

RegistreNom / rôleÀ retenir
CO (PC)Compteur ordinalAdresse de la prochaine instruction ; incrémenté après recherche, modifié par un saut.
RIRegistre instructionContient l'instruction lue en mémoire ; le code opération part vers le décodeur.
RT / RMRegistre temporaire / motZone intermédiaire pour les données ou l'instruction lue, selon le schéma du support.
ACCAccumulateurContient un opérande avant l'opération et le résultat après l'opération.

Après une comparaison CMP entre ACC et une valeur, le support utilise Z = 1 si ACC = valeur, G = 1 si ACC est supérieur, B = 1 si ACC est inférieur. Un seul de ces trois indicateurs vaut 1 dans cette comparaison simple.

4.3 — Décodeur, séquenceur et UAL

Le décodeur identifie l'opération à partir du code opération de l'instruction. Le séquenceur organise les micro-étapes et génère les signaux de commande, synchronisés par l'horloge. Ne pas confondre : le décodeur reconnaît ; le séquenceur orchestre.

L'UAL reçoit les opérandes depuis des registres (ACC et registre temporaire), réalise le calcul, puis dépose le résultat dans ACC et met à jour les indicateurs pertinents.

5.1 — Cycle d'instruction : recherche puis exécution

Le processeur répète un cycle. Dans le modèle simplifié du cours, le cycle de recherche se déroule ainsi :

  1. Transférer l'adresse contenue dans CO vers RA.
  2. Lire l'instruction en mémoire et la placer dans RM.
  3. Transférer l'instruction de RM vers RI.
  4. Envoyer le code opération au décodeur.
  5. Incrémenter CO pour préparer l'instruction suivante.

Ensuite vient le cycle d'exécution : récupérer les opérandes nécessaires, réaliser l'opération dans l'UAL ou déclencher un transfert, puis enregistrer le résultat. Un saut modifie CO et remplace l'adresse séquentielle prévue.

Pour un exercice de trace, distinguer systématiquement recherche et exécution. La lecture de l'opérande d'un ADD appartient à l'exécution, alors que le décodage appartient à la recherche.

5.2 — Jeu d'instructions assembleur du support

InstructionEffetCode opération indiqué
LOAD XACC ← contenu de X0E
ADD XACC ← ACC + X1E
SUB XACC ← ACC − X2E
MUL XACC ← ACC × X3E
NOT XComplément logique de X4E

JZ LSaut si Z = 1EF

Les codes ci-dessus sont ceux du jeu pédagogique du support. Ils ne représentent pas l'encodage universel d'un processeur réel. Le support illustre une instruction par un code opération suivi d'une adresse sur un format simplifié.

Exemple : calculer C = A + B

ASSEMBLEUR
LOAD A
ADD B
STORE C

Si A = 7 et B = 5 : LOAD A donne ACC = 7 ; ADD B donne ACC = 12 ; STORE C écrit 12 dans C. Le CO avance après chaque instruction ordinaire.

Exemple : calculer D = (A + B) × C

ASSEMBLEUR
LOAD A
ADD B
MUL C
STORE D

Pour A = 3, B = 4, C = 5 : ACC prend successivement 3, 7, puis 35 ; D reçoit 35. L'ordre des instructions est important : MUL avant ADD calculerait A + (B × C).

5.3 — Modes d'adressage

ModeExempleInterprétation
ImmédiatLOAD #20La valeur 20 est directement dans l'instruction.
DirectLOAD 2020 est l'adresse de la case dont on charge le contenu.
IndirectLOAD (20)La case 20 contient l'adresse de la donnée finale.

Exemple du support : mémoire[20] = 30 et mémoire[30] = 07. LOAD #20 donne ACC = 20 ; LOAD 20 donne ACC = 30 ; LOAD (20) donne ACC = 07. L'adressage indirect nécessite un accès mémoire supplémentaire pour retrouver l'adresse effective.

Partie 02

Exercices et problèmes corrigés

La difficulté augmente progressivement : commence par les bases, puis entraîne-toi sur les problèmes de synthèse.

Exercice 1 — Analyse d'un système informatiqueFacile
Une salle informatique contient 18 PC, un serveur de fichiers, un commutateur réseau, des écrans, des claviers, Ubuntu et un logiciel de traitement de texte.
  1. Identifier des éléments matériels et logiciels.
  2. Classer clavier, écran, serveur de fichiers et commutateur selon leur rôle d'entrée/sortie ou de communication.
  3. Décrire les couches mobilisées lorsqu'un étudiant ouvre un document puis l'enregistre.
  4. Expliquer pourquoi le logiciel ne peut pas fonctionner sans matériel.
Correction détaillée

1. Matériel : PC, serveur, commutateur, écrans, claviers. Logiciels : Ubuntu (système d'exploitation) et traitement de texte (application).
2. Clavier : entrée ; écran : sortie ; serveur de fichiers : stockage/échange bidirectionnel dans le réseau ; commutateur : équipement réseau qui transfère les trames entre ports, ce n'est pas un périphérique utilisateur classique de la liste entrée/sortie.
3. L'utilisateur agit dans l'application ; l'application demande au système d'exploitation d'ouvrir ou d'écrire le fichier ; le système d'exploitation utilise les pilotes et le matériel de stockage/réseau.
4. Un logiciel est un ensemble d'instructions : il doit être stocké et exécuté par des composants physiques.

Exercice 2 — Bus et architectureFacile → moyen
Une machine possède une UCT, une mémoire unique pour les instructions et les données, un clavier, un écran et un SSD.
  1. Nommer les trois bus et leur rôle.
  2. Justifier le sens du bus d'adresses et celui du bus de données.
  3. Identifier l'architecture représentée.
  4. Donner une différence structurelle avec Harvard et un avantage possible de cette séparation.
  5. Classer clavier, écran et SSD.
Correction détaillée

1. Bus d'adresses : sélectionne une case ; bus de données : transporte instruction/donnée ; bus de commande : lecture/écriture et signaux de contrôle.
2. L'UCT choisit l'adresse, d'où le sens UCT vers mémoire. Les données vont dans les deux sens car on lit et on écrit.
3. Von Neumann, puisque programme et données partagent une mémoire.
4. Harvard sépare mémoire programme et mémoire données, ce qui permet des accès distincts et parfois simultanés.
5. Clavier entrée, écran sortie, SSD entrée/sortie.

Exercice 3 — Hiérarchie et technologie mémoireMoyen
On compare registres, cache, DRAM, SRAM, ROM, EEPROM et Flash.
  1. Classer registres, cache, mémoire centrale et SSD de la plus rapide à la plus lente.
  2. Indiquer la volatilité de chaque technologie.
  3. Expliquer pourquoi la SRAM est utilisée pour le cache alors que la DRAM est utilisée comme mémoire centrale.
  4. Une mémoire transfère 4 octets par cycle de 25 ns. Calculer son débit théorique en octets/s puis en Mo/s décimaux.
  5. Expliquer pourquoi le temps de cycle ne peut pas être inférieur au temps d'accès dans le modèle étudié.
Correction détaillée

1. Registres → cache → mémoire centrale (DRAM) → SSD.
2. SRAM et DRAM : volatiles ; ROM, EEPROM et Flash : non volatiles.
3. SRAM : rapide, pas de rafraîchissement, mais chère et moins dense ; DRAM : plus dense et moins coûteuse, mais nécessite un rafraîchissement.
4. 25 ns = 25 × 10⁻⁹ s. Débit = 4 / (25 × 10⁻⁹) = 160 000 000 octets/s = 160 Mo/s (base décimale).
5. Le cycle doit laisser le temps de terminer l'accès avant de lancer le suivant.

Exercice 4 — Capacité d'adressageMoyen
Une mémoire possède 12 fils d'adresses et 16 fils de données.
  1. Calculer le nombre de cases adressables.
  2. Déterminer la taille d'une case en octets.
  3. Calculer la capacité totale en octets puis en Kio.
  4. Donner la plus grande adresse en hexadécimal.
  5. Déterminer le nombre de fils d'adresses nécessaire pour 128 Kio organisée en mots de 16 bits.
Correction détaillée

1. CA = 2¹² = 4096 cases.
2. 16 bits = 2 octets par case.
3. CM = 4096 × 2 = 8192 octets = 8 Kio.
4. Adresse maximale = 2¹² − 1 = 4095 = FFF₁₆.
5. 128 Kio = 131072 octets. Un mot = 2 octets, donc 65536 mots = 2¹⁶ ; il faut 16 fils d'adresses.

Exercice 5 — Plan mémoire avec zones libresDifficile
Une machine possède un bus d'adresses de 20 bits et un bus de données de 8 bits. La ROM de 96 Kio commence à 00000₁₆. La RAM de 160 Kio commence à 30000₁₆.
  1. Calculer l'espace total adressable en octets.
  2. Calculer les adresses de fin inclusives de la ROM et de la RAM.
  3. Vérifier que les blocs ne se chevauchent pas.
  4. Calculer le nombre d'octets libres entre la fin de la ROM et le début de la RAM.
  5. Calculer l'espace restant après la RAM jusqu'à la dernière adresse du bus.
Correction détaillée

1. 2²⁰ = 1 048 576 octets = 1 Mio, puisque le bus de données adresse des octets (8 bits).
2. 96 Kio = 0x18000 octets ; fin ROM = 0x00000 + 0x18000 − 1 = 0x17FFF. 160 Kio = 0x28000 octets ; fin RAM = 0x30000 + 0x28000 − 1 = 0x57FFF.
3. ROM finit à 17FFF et RAM commence à 30000 : pas de chevauchement.
4. Cases libres = 30000 − 18000 = 18000₁₆ octets = 98304 octets = 96 Kio. (L'adresse 17FFF est incluse dans la ROM, 18000 est la première adresse libre.)
5. Espace après RAM = 100000₁₆ − 58000₁₆ = 0xA8000 octets = 688128 octets = 672 Kio.

Exercice 6 — Registres et instruction machineDifficile
Une UCT dispose de CO, RI, ACC, RE, RA et RM.
  1. Associer chaque registre à son rôle.
  2. Un CO de 12 bits adresse combien de mots ?
  3. Il vaut 0FF2₁₆ avant la recherche d'une instruction ordinaire. Donner sa valeur après incrémentation.
  4. Une instruction de 16 bits contient 6 bits de code opération et 10 bits d'adresse. Combien d'opérations et d'adresses distinctes peut-on coder ?
  5. Expliquer la différence entre décodeur et séquenceur.
Correction détaillée

1. CO : adresse de la prochaine instruction ; RI : instruction courante ; ACC : opérande/résultat ; RE : indicateurs ; RA : adresse mémoire ; RM : registre temporaire contenant le mot lu.
2. 2¹² = 4096 mots.
3. 0FF2₁₆ + 1 = 0FF3₁₆.
4. 2⁶ = 64 codes opération ; 2¹⁰ = 1024 adresses directes.
5. Le décodeur reconnaît l'opération à partir du code ; le séquenceur génère les signaux et ordonne les micro-étapes.

Exercice 7 — Trace complète d'un programmeDifficile
On utilise le jeu d'instructions du cours. A=12, B=4, C=3 et D est initialement indéfini. Programme : 
LOAD A
SUB B
MUL C
STORE D
  1. Donner ACC après chaque instruction.
  2. Donner la valeur finale de D.
  3. Donner le nombre d'instructions exécutées.
  4. Si le CO commence à 20₁₆ et chaque instruction occupe un mot, donner les valeurs successives du CO après chaque recherche.
  5. Expliquer ce qui changerait si MUL C était placé avant SUB B.
Correction détaillée

1. LOAD A : ACC=12 ; SUB B : ACC=8 ; MUL C : ACC=24 ; STORE D : D=24 et ACC reste 24.
2. D=24.
3. Quatre instructions.
4. Les adresses des instructions sont 20,21,22,23₁₆ ; après les recherches, CO vaut successivement 21,22,23,24₁₆.
5. Avec MUL avant SUB, on calculerait (A×C)−B = 36−4 = 32, au lieu de (A−B)×C = 24.

Exercice 8 — Comparaison et branchementsTrès difficile
On veut ranger le maximum de A et B dans MAX. Le programme utilise LOAD, CMP, JG, LOAD, STORE.
  1. Écrire le programme correct.
  2. Tracer ACC et Z/G/B pour A=4, B=9.
  3. Tracer le programme pour A=10, B=3.
  4. Expliquer pourquoi le branchement doit être placé juste après CMP.
  5. Modifier le programme pour ranger 1 dans EGAL si A=B et 0 sinon.
Correction détaillée

1.

LOAD A
CMP B
JG GARDE
LOAD B
JMP FIN
GARDE: LOAD A
FIN: STORE MAX
(On peut aussi laisser ACC=A au label GARDE en sautant directement vers STORE MAX.)
2. A=4 : LOAD donne ACC=4 ; CMP B donne Z=0,G=0,B=1 ; JG ne saute pas ; LOAD B donne ACC=9 ; MAX=9.
3. A=10 : CMP donne Z=0,G=1,B=0 ; JG saute ; MAX=10.
4. CMP établit les indicateurs ; une instruction arithmétique entre CMP et JG pourrait les modifier.
5.
LOAD A
CMP B
JZ EGAL
LOAD ZERO
JMP FIN
EGAL: LOAD UN
FIN: STORE EGALITE
ZERO=0, UN=1. Attention à distinguer le nom de l'étiquette EGAL et la variable EGALITE.

Exercice 9 — Modes d'adressage et code machineTrès difficile
On donne mémoire[20₁₆]=30₁₆ et mémoire[30₁₆]=07₁₆. R1 contient 12.
  1. Calculer ACC après LOAD #20, LOAD 20, LOAD (20), LOAD R1.
  2. Expliquer le nombre d'accès mémoire nécessaire dans chaque mode.
  3. Le code opération de LOAD vaut 0E et l'adresse de A vaut 20₁₆. Écrire l'encodage hexadécimal pédagogique de LOAD A.
  4. Écrire l'encodage binaire correspondant.
  5. Pourquoi ne faut-il pas présenter ces octets comme un code machine universel ?
Correction détaillée

1. LOAD #20 → ACC=20 (valeur immédiate) ; LOAD 20 → ACC=30 (contenu de la case 20) ; LOAD (20) → ACC=07 (la case 20 contient l'adresse 30, puis on lit cette case) ; LOAD R1 → ACC=12.
2. Immédiat : la constante est dans l'instruction ; direct : lecture de la case indiquée ; indirect : lecture du pointeur puis lecture de la donnée ; registre : valeur dans R1, sans lecture de l'opérande en mémoire.
3. 0E20.
4. 0000 1110 0010 0000.
5. Il s'agit du format simplifié et du jeu de codes définis par le support pédagogique, non d'une ISA standard comme x86 ou ARM.

Exercice 10 — Synthèse type examenTrès difficile
Une machine utilise des mots de 16 bits, un CO de 16 bits, une mémoire adressée par mots et le jeu d'instructions pédagogique. Le programme calcule le maximum de trois températures T1,T2,T3 et place le résultat dans MAX.
  1. Proposer un algorithme en français.
  2. Écrire un programme assembleur utilisant uniquement LOAD, CMP, JG, STORE et les branchements nécessaires.
  3. Tracer les indicateurs et ACC pour T1=28,T2=31,T3=25.
  4. Calculer le nombre de mots adressables et l'adresse maximale.
  5. Une instruction contient 8 bits d'opcode et 8 bits d'adresse : donner le nombre de codes et d'adresses possibles.
  6. Expliquer les limites du modèle pédagogique par rapport à un processeur réel.
Correction détaillée

1. Initialiser le maximum avec T1 ; comparer ce maximum à T2 et le remplacer si T2 est supérieur ; recommencer avec T3 ; stocker MAX.
2.

LOAD T1
CMP T2
JG GARDE2
LOAD T2
GARDE2: CMP T3
JG GARDE3

GARDE3: STORE MAX

3. LOAD T1 : ACC=28. CMP T2 : G=0,B=1 ; on charge T2=31. CMP T3 : G=1 ; on conserve 31. STORE MAX : MAX=31.
4. 2¹⁶=65536 mots, adresses 0000₁₆ à FFFF₁₆.
5. 2⁸=256 opcodes et 256 adresses.
6. Le modèle simplifie les formats, les registres, les modes et les timings ; les codes ne sont pas ceux d'une architecture commerciale réelle.
