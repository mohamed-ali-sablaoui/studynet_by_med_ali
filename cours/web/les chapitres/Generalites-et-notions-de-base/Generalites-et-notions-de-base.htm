Généralités et notions de base

Comprendre Internet, le Web et l’architecture des applications Web. Un cours organisé, des devoirs avec corrections et une évaluation aléatoire pour vérifier ta maîtrise.

Cours complet

Ouvre chaque notion pour lire les explications, les règles et les exemples. Les exemples de code sont à adapter à ton projet.

01. 1. Internet, Web et réseau

Internet est une infrastructure mondiale qui relie des réseaux informatiques. Les machines communiquent en utilisant une famille de protocoles, notamment TCP/IP. Le Web (World Wide Web) est un service qui fonctionne au-dessus d’Internet : il permet de consulter des ressources reliées par des hyperliens.

Il ne faut donc jamais confondre Internet et Web. Internet transporte plusieurs services : Web, courrier électronique, transfert de fichiers, appels en ligne, etc. Le Web est l’un de ces services.

Exemple : ouvrir un site avec Chrome utilise le Web. Envoyer un e-mail utilise Internet, mais pas nécessairement le Web.
02. 2. Réseaux, protocoles et adresses

Un réseau permet à des équipements d’échanger des informations. Une adresse IP identifie une interface sur un réseau. Un nom de domaine (ex. exemple.tn) est plus facile à mémoriser qu’une adresse IP.

Le DNS (Domain Name System) traduit un nom de domaine en adresse IP. TCP assure notamment un transport fiable et ordonné des données ; IP s’occupe de l’adressage et de l’acheminement des paquets. Les protocoles définissent les règles de communication.

Une URL identifie une ressource. Exemple : https://www.exemple.tn/cours/page.html?id=5#partie2 : protocole HTTPS, hôte www.exemple.tn, chemin /cours/page.html, paramètre id=5 et fragment partie2.

03. 3. Historique : d’ARPANET au WWW

Le cours situe les premières recherches sur les réseaux à l’époque de la guerre froide. L’ARPA est créée aux États-Unis en 1958 ; ARPANET apparaît à la fin des années 1960. Les premiers réseaux utilisent différents protocoles, puis la famille TCP/IP permet l’interconnexion de réseaux hétérogènes.

Dans les années 1980, TCP/IP devient la base de l’Internet moderne. À la fin des années 1980, Tim Berners-Lee propose au CERN un système de documents reliés par hypertexte. Le Web se développe au début des années 1990 avec les URL, HTTP et HTML.

À retenir : ARPANET est un précurseur historique ; Internet est l’infrastructure réseau ; le Web est un service bâti sur cette infrastructure.
04. 4. Évolution du Web

Le Web 1.0 est souvent décrit comme un Web principalement consultatif : les pages sont relativement statiques et l’utilisateur lit surtout l’information. Le Web 2.0 met l’accent sur la participation, les échanges et la production de contenu par les utilisateurs : réseaux sociaux, blogs, wikis et plateformes collaboratives.

Le terme Web 3.0 est utilisé dans plusieurs sens. Dans le support de cours, il renvoie notamment au Web sémantique ou « smart web », où les données sont mieux décrites pour faciliter leur interprétation et leur exploitation. Dans l’usage contemporain, le terme peut aussi désigner d’autres approches ; il faut donc préciser le contexte.

05. 5. Fonctionnement client–serveur

Dans un modèle client–serveur, le client demande une ressource ou un service ; le serveur reçoit la demande, effectue le traitement nécessaire et renvoie une réponse. Dans une consultation Web, le navigateur joue généralement le rôle du client.

  1. L’utilisateur saisit une URL.
  2. Le navigateur résout le nom de domaine grâce au DNS.
  3. Il établit une connexion avec le serveur (HTTPS utilise TLS).
  4. Il envoie une requête HTTP.
  5. Le serveur renvoie une réponse (statut, en-têtes et éventuellement contenu).
  6. Le navigateur interprète HTML, applique CSS et exécute JavaScript.
Exemple : demander /produits peut déclencher une requête ; le serveur récupère les produits et renvoie une page ou des données.
06. 6. HTTP, HTTPS et navigateur

HTTP est un protocole de requête/réponse. Une requête contient une méthode (GET, POST…), une cible, des en-têtes et parfois un corps. La réponse contient un code d’état, des en-têtes et éventuellement un corps.

  • GET : demander une représentation d’une ressource ;
  • POST : transmettre des données pour traitement ou création ;
  • PUT/PATCH : remplacer ou modifier une ressource selon l’API ;
  • DELETE : demander la suppression d’une ressource.

HTTPS correspond à HTTP protégé par TLS : confidentialité du transport, intégrité et authentification du serveur selon le certificat. HTTPS ne garantit pas à lui seul que le contenu d’un site est honnête.

07. 7. Site statique et site dynamique

Un site statique sert des fichiers préparés (HTML, CSS, images…). Le contenu ne dépend pas nécessairement d’un traitement à chaque visite. Un site dynamique peut générer une réponse selon l’utilisateur, les paramètres ou les données d’une base.

Le dynamisme peut être côté client (JavaScript modifie la page dans le navigateur) ou côté serveur (PHP, par exemple, produit du HTML après un traitement). Les deux approches peuvent être combinées.

08. 8. Les trois niveaux d’une application

Le support distingue trois niveaux d’abstraction :

  1. Présentation : interface avec laquelle l’utilisateur interagit ; pages, formulaires, boutons.
  2. Traitements / logique métier : règles de l’application, contrôles, calculs et décisions.
  3. Données : stockage, consultation, modification et suppression des informations.

Exemple d’inscription : le formulaire est la présentation ; vérifier l’adresse e-mail et appliquer les règles d’inscription est le traitement ; enregistrer l’étudiant dans la base est la couche données.

09. 9. Architectures 1, 2, 3 et n tiers

Un tiers (maître–esclave / centralisée) : les couches applicatives sont regroupées sur un ordinateur central ; les terminaux dépendent de ce système. Déploiement centralisé, mais risque de surcharge et maintenance parfois difficile.

Deux tiers (client–serveur de données) : le client possède l’interface et souvent une grande partie des traitements ; le serveur centralise les données et répond aux requêtes, souvent SQL. Avantages : interface riche et données centralisées. Limites : client lourd, mises à jour sur les postes, évolutivité limitée.

Trois tiers : présentation côté client, traitements sur un serveur applicatif, données sur un serveur de base de données. La séparation facilite la maintenance, la sécurité et l’évolution.

N tiers : le système est réparti en plusieurs couches ou services. Cela permet une séparation plus fine, mais augmente les besoins de conception, de supervision et de communication entre composants.

10. 10. Middleware, serveur et hébergement

Un middleware regroupe des logiciels ou services intermédiaires facilitant le dialogue entre composants répartis. Un serveur Web reçoit les requêtes HTTP et sert des ressources ou transmet le travail à une application. Un serveur applicatif exécute la logique métier. Un SGBD gère les données.

L’hébergement consiste à rendre les ressources accessibles depuis un serveur. Le nom de domaine, le DNS, le serveur Web, le certificat TLS et la configuration des chemins font partie des éléments à vérifier lors de la publication.

11. 11. Méthode de réalisation d’un site
  1. Analyser le besoin, les utilisateurs et les objectifs.
  2. Définir les contenus et l’arborescence.
  3. Réaliser une maquette et choisir une navigation claire.
  4. Structurer le contenu avec HTML.
  5. Présenter la page avec CSS.
  6. Ajouter les interactions nécessaires avec JavaScript et les traitements serveur.
  7. Tester les liens, formulaires, affichages mobiles, clavier et navigateurs.
  8. Publier, sauvegarder, surveiller et maintenir.

Un bon site n’est pas seulement joli : il doit répondre au besoin, être compréhensible, accessible, rapide, fiable et maintenable.

Méthode de travail : lis une notion, reproduis l’exemple dans ton éditeur, modifie une valeur, puis explique avec tes propres mots le résultat obtenu.

Exercices et problèmes

Résous le sujet sur papier ou dans ton éditeur avant de révéler la correction. Les sujets couvrent plusieurs notions du chapitre.

Devoir 01 — Analyse d’un parcours Web

Un étudiant saisit https://cours.exemple.tn/chapitre.html dans son navigateur. Décrire les étapes de résolution du nom jusqu’à l’affichage, en citant DNS, HTTPS, serveur et navigateur.

Correction proposée

Le navigateur extrait le nom de domaine, demande au DNS l’adresse IP, établit une connexion sécurisée TLS, envoie une requête HTTP (ici HTTPS) au serveur. Le serveur renvoie une réponse avec un statut et un contenu. Le navigateur interprète le HTML, applique le CSS et exécute le JavaScript.

Devoir 02 — Étude de cas — portail étudiant

Un portail affiche les notes enregistrées dans une base. Identifier les trois couches, donner le rôle de chacune et tracer le trajet d’une demande.

Correction proposée

Présentation : navigateur et formulaire. Traitements : serveur applicatif vérifie l’identité, applique les règles et demande les notes. Données : SGBD stocke étudiants et notes. Flux : navigateur → serveur applicatif → SGBD → serveur applicatif → navigateur.

Devoir 03 — Comparaison des architectures

Comparer 1-tier, 2-tiers et 3-tiers selon répartition, avantage et limite. Donner un exemple réaliste de chaque.

Correction proposée

1-tier : centralisé, déploiement central facile mais surcharge possible. 2-tiers : client riche connecté directement au serveur de données, données centralisées mais client lourd et déploiement client. 3-tiers : présentation/traitement/données séparés, maintenance et évolutivité améliorées mais architecture plus complexe.

Devoir 04 — Diagnostic d’un site

Une page HTML locale fonctionne sans base de données. Une autre affiche un panier personnalisé selon le compte connecté. Classer les deux et justifier.

Correction proposée

La première peut être statique. La seconde est dynamique : elle dépend d’un utilisateur, d’une session et probablement de données persistantes. JavaScript seul peut dynamiser l’interface, mais la personnalisation fiable nécessite un traitement serveur.

Devoir 05 — Devoir — Web ou Internet ?

Pour chaque situation, préciser si elle relève du Web, d’un autre service Internet ou d’un outil client : consulter un article, envoyer un e-mail depuis un logiciel, saisir une URL, résoudre un nom de domaine.

Correction proposée

Consulter un article : Web. Envoyer un e-mail : service de messagerie sur Internet. Saisir une URL : action dans un navigateur, client Web. Résoudre un nom : DNS, service d’infrastructure réseau.

Devoir 06 — Schéma d’architecture

Dessiner l’architecture 3-tiers d’une application de réservation et indiquer au moins deux données et deux traitements.

Correction proposée

Présentation : pages de recherche et réservation. Traitements : disponibilité, calcul du prix, validation de réservation. Données : utilisateurs, créneaux, réservations. Le navigateur ne doit pas accéder directement à la base ; il communique avec le serveur applicatif.
