CHAPITRE 01

Introduction aux bases de données

1.1 Qu'est-ce qu'une donnée ?

Une donnée est une information brute qui peut être enregistrée et utilisée par un système informatique.

Exemples :

  • Mohamed : nom d'une personne.
  • 20 : âge d'une personne.
  • mohamed@example.com : adresse électronique.
  • 150 : prix d'un produit.
  • 2026-11-08 : date.

1.2 Qu'est-ce qu'une base de données ?

Définition : Une base de données est un ensemble structuré de données enregistrées de manière organisée afin de faciliter leur consultation, leur modification et leur gestion.

Prenons l'exemple d'un établissement universitaire. Il doit conserver les informations des étudiants, des enseignants, des matières et des notes.

Sans base de données, ces informations pourraient être dispersées dans plusieurs fichiers. Cela rendrait leur gestion difficile.

1.3 Pourquoi utiliser une base de données ?

  • Stockage : conserver les informations.
  • Organisation : classer les données.
  • Recherche : retrouver rapidement une information.
  • Modification : mettre à jour les informations.
  • Sécurité : contrôler les accès.
  • Cohérence : éviter les données contradictoires.
  • Partage : permettre à plusieurs utilisateurs de travailler sur les mêmes données.

1.4 Exemple concret

Imaginons une table qui contient les étudiants d'un établissement.

ID Nom Prénom Âge Classe
1AliMohamed20TI1
2Ben SalahAmira19TI1
3TrabelsiYoussef21TI2
Chaque ligne représente un étudiant. Chaque colonne représente une information concernant cet étudiant.

1.5 Différence entre données et informations

Donnée

Une valeur isolée : 20, Mohamed, TI1.

Information

Mohamed est un étudiant âgé de 20 ans inscrit en TI1.

CHAPITRE 02

Les systèmes de gestion de bases de données (SGBD)

2.1 Qu'est-ce qu'un SGBD ?

Un SGBD (Système de Gestion de Bases de Données) est un logiciel qui permet de créer, organiser, consulter, modifier et sécuriser une base de données.

La base de données contient les données. Le SGBD est le logiciel qui permet de gérer ces données.

2.2 Exemples de SGBD

MySQL

SGBD relationnel très utilisé dans les applications web.

PostgreSQL

SGBD relationnel puissant avec de nombreuses fonctionnalités.

SQLite

SGBD léger qui stocke la base dans un fichier.

Microsoft SQL Server

SGBD relationnel développé par Microsoft.

Oracle Database

SGBD utilisé notamment dans les grandes organisations.

MongoDB

Base de données orientée documents, de type NoSQL.

2.3 Les principales fonctions d'un SGBD

  • Créer et supprimer des bases de données.
  • Créer et modifier des tables.
  • Enregistrer et rechercher des données.
  • Gérer les utilisateurs et les permissions.
  • Gérer les accès simultanés.
  • Assurer la sauvegarde et la restauration.
  • Maintenir l'intégrité des données.

2.4 SGBD relationnel et NoSQL

Relationnel NoSQL
Données organisées en tables. Différents modèles de stockage.
Relations entre les tables. Documents, clés-valeurs, graphes, etc.
SQL généralement utilisé. Langages et interfaces variables.
Exemple : MySQL. Exemple : MongoDB.
CHAPITRE 03

La modélisation d'une base de données

3.1 Pourquoi modéliser ?

Avant de créer une base de données, il faut réfléchir à sa structure. La modélisation consiste à représenter les données et les relations nécessaires au fonctionnement d'un système.

Une bonne modélisation permet d'éviter les répétitions, les incohérences et les difficultés de modification.

3.2 Les trois niveaux de modélisation

Modèle conceptuel (MCD)

Il décrit les données et les relations entre elles, sans dépendre d'un SGBD particulier.

Modèle logique (MLD)

Il transforme les entités et les associations en structures logiques, généralement des tables.

Modèle physique (MPD)

Il décrit l'implémentation réelle dans un SGBD : types SQL, contraintes, index et autres éléments techniques.

3.3 Les entités

Une entité représente un objet ou un élément du monde réel dont on souhaite conserver des informations.

Exemples :

  • Étudiant
  • Enseignant
  • Produit
  • Commande
  • Client

3.4 Les attributs

Un attribut représente une caractéristique d'une entité. Par exemple, l'entité Étudiant peut posséder les attributs suivants :

  • id_etudiant
  • nom
  • prenom
  • email
  • date_naissance

3.5 Les associations

Une association représente un lien entre plusieurs entités.

Exemple : un étudiant s'inscrit à plusieurs cours. Un cours peut accueillir plusieurs étudiants. Il existe donc une association entre Étudiant et Cours.

3.6 Exemple de modélisation

Pour une petite bibliothèque, on identifie :

  • Adherent : personne qui emprunte des livres.
  • Livre : ouvrage disponible dans la bibliothèque.
  • Emprunt : opération qui relie un adhérent à un livre.

4.4 Règles importantes

  • Chaque colonne possède un nom.

  • Les relations entre tables sont établies grâce aux clés.
CHAPITRE 05

Les clés et les contraintes d'intégrité

5.1 Clé primaire (PRIMARY KEY)

Une clé primaire est un attribut, ou un ensemble d'attributs, qui identifie de manière unique chaque ligne d'une table.

Une clé primaire doit être unique et ne peut pas être NULL.

SQL · PRIMARY KEY 
CREATE TABLE Etudiant (
    id_etudiant INT PRIMARY KEY,
    nom VARCHAR(50),
    prenom VARCHAR(50)
);
Explication : id_etudiant identifie chaque étudiant. Deux étudiants ne peuvent pas avoir la même valeur de clé primaire.

5.2 Clé étrangère (FOREIGN KEY)

Une clé étrangère est un attribut qui fait référence à une clé primaire ou à une clé candidate unique d'une autre table. Elle permet d'établir une relation entre les tables.

SQL · FOREIGN KEY 
CREATE TABLE Classe (
    id_classe INT PRIMARY KEY,
    nom_classe VARCHAR(30)
);

CREATE TABLE Etudiant (
    id_etudiant INT PRIMARY KEY,
    nom VARCHAR(50),
    id_classe INT,
    FOREIGN KEY (id_classe)
        REFERENCES Classe(id_classe)
);
Explication : La colonne id_classe de la table Etudiant référence la colonne id_classe de Classe. Un étudiant ne peut donc pas référencer une classe inexistante.

5.3 Les contraintes SQL

Contrainte Rôle
PRIMARY KEYIdentifie chaque ligne.
FOREIGN KEYGarantit une référence valide.
NOT NULLInterdit une valeur NULL.
UNIQUEInterdit les doublons.
CHECKImpose une condition.
DEFAULTDéfinit une valeur par défaut.

5.4 NOT NULL et UNIQUE

SQL · NOT NULL et UNIQUE 
CREATE TABLE Utilisateur (
    id INT PRIMARY KEY,
    nom VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE
);
Explication : Le nom est obligatoire grâce à NOT NULL. L'adresse email doit être différente pour chaque utilisateur grâce à UNIQUE.

5.5 CHECK et DEFAULT

SQL · CHECK et DEFAULT 
CREATE TABLE Produit (
    id INT PRIMARY KEY,
    nom VARCHAR(80) NOT NULL,
    prix DECIMAL(10,2) CHECK (prix >= 0),
    stock INT DEFAULT 0
);
Explication : Le prix ne peut pas être négatif. Si aucune valeur de stock n'est fournie lors de l'insertion, sa valeur sera 0.
CHAPITRE 06

La normalisation

6.1 Pourquoi normaliser une base de données ?

La normalisation consiste à organiser les tables afin de réduire les répétitions inutiles et d'éviter certaines anomalies.

Objectif : améliorer la cohérence des données et faciliter leur maintenance.

6.2 Les anomalies

  • Anomalie d'insertion : difficulté à ajouter une information.
  • Anomalie de modification : obligation de modifier plusieurs lignes.
  • Anomalie de suppression : suppression involontaire d'une information utile.

6.3 Première forme normale (1FN)

Une table respecte la première forme normale si chaque cellule contient une valeur atomique, c'est-à-dire une seule valeur pour l'attribut considéré.

Une cellule ne doit pas contenir une liste de plusieurs valeurs qui devraient être représentées séparément.

6.4 Deuxième forme normale (2FN)

Une table est en deuxième forme normale si elle respecte la 1FN et si chaque attribut non-clé dépend de toute la clé primaire, et non d'une partie seulement d'une clé composée.

6.5 Troisième forme normale (3FN)

Une table est en troisième forme normale si elle respecte la 2FN et ne présente pas de dépendance transitive entre attributs non-clés.

6.6 Exemple de séparation

Au lieu de répéter les informations d'une classe dans chaque ligne d'étudiant, on crée une table Classe séparée.

Structure normalisée 
CREATE TABLE Classe (
    id_classe INT PRIMARY KEY,
    nom_classe VARCHAR(30)
);

CREATE TABLE Etudiant (
    id_etudiant INT PRIMARY KEY,
    nom VARCHAR(50),
    id_classe INT,
    FOREIGN KEY (id_classe)
        REFERENCES Classe(id_classe)
);
Explication : Les informations de la classe sont enregistrées une seule fois dans Classe. Les étudiants utilisent son identifiant pour indiquer leur classe.
CHAPITRE 07

Les relations entre les tables

7.1 Relation un-à-un (1:1)

Une ligne de la première table est associée à une seule ligne de la deuxième table, et inversement.

Exemple : une personne possède un seul passeport actif dans un système simplifié.

7.2 Relation un-à-plusieurs (1:N)

Une ligne de la première table peut être associée à plusieurs lignes de la deuxième table.

Exemple : une classe contient plusieurs étudiants.

SQL · Relation 1:N 
CREATE TABLE Classe (
    id INT PRIMARY KEY,
    nom VARCHAR(30)
);

CREATE TABLE Etudiant (
    id INT PRIMARY KEY,
    nom VARCHAR(50),
    classe_id INT,
    FOREIGN KEY (classe_id) REFERENCES Classe(id)
);

7.3 Relation plusieurs-à-plusieurs (N:N)

Plusieurs lignes de la première table peuvent être associées à plusieurs lignes de la deuxième table.

Exemple : un étudiant suit plusieurs matières et une matière est suivie par plusieurs étudiants.

Pour représenter une relation N:N dans un modèle relationnel, on utilise généralement une table intermédiaire.
SQL · Table intermédiaire 
CREATE TABLE Etudiant (
    id_etudiant INT PRIMARY KEY,
    nom VARCHAR(50)
);

CREATE TABLE Matiere (
    id_matiere INT PRIMARY KEY,
    nom_matiere VARCHAR(50)
);

CREATE TABLE Inscription (
    etudiant_id INT,
    matiere_id INT,
    date_inscription DATE,
    PRIMARY KEY (etudiant_id, matiere_id),
    FOREIGN KEY (etudiant_id)
        REFERENCES Etudiant(id_etudiant),
    FOREIGN KEY (matiere_id)
        REFERENCES Matiere(id_matiere)
);
Explication : La table Inscription associe un étudiant à une matière. Sa clé primaire est composée de deux colonnes. Cette structure permet d'éviter qu'un même étudiant soit inscrit plusieurs fois à la même matière dans cet exemple.
CHAPITRE 08

Introduction au langage SQL

8.1 Qu'est-ce que SQL ?

SQL signifie Structured Query Language. C'est un langage utilisé pour communiquer avec les systèmes de gestion de bases de données relationnelles.

SQL permet notamment de :

  • Créer une base de données.
  • Créer des tables.
  • Insérer des données.
  • Lire et rechercher des données.
  • Modifier des données.
  • Supprimer des données.
  • Gérer les droits et les transactions.

8.2 Les grandes familles de commandes SQL

Famille Signification Commandes
DDLDéfinition des structuresCREATE, ALTER, DROP
DMLManipulation des donnéesINSERT, UPDATE, DELETE
DQLInterrogation des donnéesSELECT
DCLContrôle des droitsGRANT, REVOKE
TCLGestion des transactionsCOMMIT, ROLLBACK

8.3 Syntaxe générale

SQL · Exemple général 
SELECT colonne
FROM nom_table
WHERE condition;
Explication : SELECT indique les colonnes à afficher. FROM indique la table à consulter. WHERE permet de filtrer les lignes selon une condition. Le point-virgule termine généralement l'instruction.
SQL est normalisé, mais certains détails de syntaxe et certaines fonctionnalités varient selon MySQL, PostgreSQL, SQLite et les autres SGBD.
CHAPITRE 09

Créer et supprimer une base de données

9.1 CREATE DATABASE

La commande CREATE DATABASE permet de créer une nouvelle base de données.

SQL · CREATE DATABASE 
CREATE DATABASE universite;
Explication : Cette instruction demande au SGBD de créer une base de données nommée universite.

9.2 Utiliser une base de données

Avec MySQL, la commande USE permet de sélectionner la base de données sur laquelle on souhaite travailler.

SQL · USE 
USE universite;

9.3 Supprimer une base de données

SQL · DROP DATABASE 
DROP DATABASE universite;
Attention : DROP DATABASE supprime la base de données et son contenu. Cette opération est destructive. Il faut vérifier le nom de la base et disposer d'une sauvegarde si nécessaire.

9.4 Éviter une erreur si la base existe déjà

SQL · IF NOT EXISTS 
CREATE DATABASE IF NOT EXISTS universite;

Cette forme est prise en charge par plusieurs SGBD, notamment MySQL et PostgreSQL, avec des particularités selon le système utilisé.

CHAPITRE 10

Créer et modifier les tables

10.1 CREATE TABLE

Une table permet de stocker des données organisées en lignes et en colonnes.

SQL · CREATE TABLE 
CREATE TABLE Etudiant (
    id INT PRIMARY KEY,
    nom VARCHAR(50),
    prenom VARCHAR(50),
    age INT,
    email VARCHAR(100)
);
Explication ligne par ligne :
  • CREATE TABLE Etudiant crée une table nommée Etudiant.
  • id INT crée une colonne entière.
  • PRIMARY KEY définit la clé primaire.
  • VARCHAR(50) autorise une chaîne de caractères de longueur maximale 50.
  • age INT stocke un nombre entier.
  • La parenthèse fermante termine la définition de la table.

10.3 ALTER TABLE

ALTER TABLE permet de modifier la structure d'une table existante.

Ajouter une colonne

SQL · ADD COLUMN 
ALTER TABLE Etudiant
ADD telephone VARCHAR(20);

Supprimer une colonne

SQL · DROP COLUMN 
ALTER TABLE Etudiant
DROP COLUMN telephone;

10.4 Supprimer une table

SQL · DROP TABLE 
DROP TABLE Etudiant;
DROP TABLE supprime la structure de la table ainsi que les données qu'elle contient. Ne pas confondre avec DELETE, qui supprime des lignes.
CHAPITRE 11

Insérer des données avec INSERT INTO

11.1 Insérer une seule ligne

INSERT INTO permet d'ajouter de nouvelles lignes dans une table.

SQL · INSERT INTO 
INSERT INTO Etudiant
(id, nom, prenom, age)
VALUES
(1, 'Ali', 'Mohamed', 20);
Explication : INSERT INTO indique la table et les colonnes concernées. VALUES fournit les valeurs dans le même ordre. Les textes sont placés entre apostrophes.

11.2 Insérer plusieurs lignes

SQL · INSERT multiple 
INSERT INTO Etudiant
(id, nom, prenom, age)
VALUES
(1, 'Ali', 'Mohamed', 20),
(2, 'Ben Salah', 'Amira', 19),
(3, 'Trabelsi', 'Youssef', 21);

11.3 Insérer sans préciser toutes les colonnes

SQL · Valeur par défaut 
INSERT INTO Produit
(id, nom)
VALUES
(1, 'Clavier');

Les colonnes non indiquées reçoivent leur valeur DEFAULT, ou NULL si cela est autorisé et qu'aucune valeur par défaut n'est définie.

11.4 Insérer une date

SQL · DATE 
INSERT INTO Commande
(id, date_commande)
VALUES
(1, '2026-11-08');
CHAPITRE 12

Consulter les données avec SELECT

12.1 SELECT *

SELECT permet de récupérer des informations depuis une ou plusieurs tables.

SQL · SELECT * 
SELECT *
FROM Etudiant;
Explication : L'étoile signifie toutes les colonnes. Cette requête affiche toutes les lignes et toutes les colonnes de la table Etudiant.

12.2 Sélectionner certaines colonnes

SQL · Colonnes précises 
SELECT nom, prenom
FROM Etudiant;

Cette requête affiche uniquement le nom et le prénom des étudiants.

12.3 DISTINCT

DISTINCT permet d'éliminer les doublons dans le résultat.

SQL · DISTINCT 
SELECT DISTINCT ville
FROM Client;

La requête affiche chaque ville une seule fois, même si plusieurs clients habitent dans la même ville.

12.4 LIMIT

SQL · LIMIT 
SELECT *
FROM Etudiant
LIMIT 5;

LIMIT 5 limite le résultat à cinq lignes dans les SGBD qui utilisent cette syntaxe, notamment MySQL et PostgreSQL.

CHAPITRE 13

Filtrer les données avec WHERE

13.1 Le rôle de WHERE

WHERE permet de sélectionner uniquement les lignes qui respectent une condition.

SQL · WHERE 
SELECT *
FROM Etudiant
WHERE age >= 20;
Explication : La requête affiche uniquement les étudiants dont l'âge est supérieur ou égal à 20.

13.2 Les opérateurs de comparaison

OpérateurSignification
=Égal à
!= ou <>Différent de
>Supérieur à
<Inférieur à

<=Inférieur ou égal à

13.3 AND

AND permet de combiner plusieurs conditions. Toutes les conditions doivent être vraies.

SQL · AND 
SELECT *
FROM Etudiant
WHERE age >= 18 AND age <= 25;

13.4 OR

OR permet de sélectionner les lignes qui respectent au moins une des conditions.

SQL · OR 
SELECT *
FROM Etudiant
WHERE ville = 'Mahdia'
OR ville = 'Sousse';

13.5 NOT

NOT inverse le résultat logique d'une condition.

SQL · NOT 
SELECT *
FROM Etudiant
WHERE NOT ville = 'Mahdia';

13.6 BETWEEN

BETWEEN vérifie si une valeur appartient à un intervalle inclusif.

SQL · BETWEEN 
SELECT *
FROM Produit
WHERE prix BETWEEN 10 AND 100;

13.7 IN

IN permet de vérifier si une valeur appartient à une liste.

SQL · IN 
SELECT *
FROM Etudiant
WHERE ville IN ('Mahdia', 'Sousse', 'Tunis');

13.8 LIKE

LIKE permet de rechercher un texte selon un modèle.

SymboleSignification
%Remplace zéro ou plusieurs caractères.
_Remplace exactement un caractère.
SQL · LIKE 
-- Les noms qui commencent par A
SELECT *
FROM Etudiant
WHERE nom LIKE 'A%';

-- Les noms qui se terminent par i
SELECT *
FROM Etudiant
WHERE nom LIKE '%i';

-- Les noms qui contiennent ali
SELECT *
FROM Etudiant
WHERE nom LIKE '%ali%';

13.9 IS NULL

NULL représente une valeur absente ou inconnue. On ne teste pas NULL avec = ou !=.

SQL · IS NULL 
SELECT *
FROM Etudiant
WHERE telephone IS NULL;

Pour rechercher les valeurs présentes :

SQL · IS NOT NULL 
SELECT *
FROM Etudiant
WHERE telephone IS NOT NULL;
CHAPITRE 14

Trier les résultats avec ORDER BY

14.1 Trier par ordre croissant

SQL · ASC 
SELECT *
FROM Etudiant
ORDER BY nom ASC;

ASC signifie ascendant : les résultats sont triés par ordre croissant. Pour les textes, l'ordre dépend des règles de comparaison et de collation du SGBD.

14.2 Trier par ordre décroissant

SQL · DESC 
SELECT *
FROM Produit
ORDER BY prix DESC;

DESC signifie descendant. Les prix les plus élevés apparaissent en premier.

14.3 Trier selon plusieurs colonnes

SQL · Tri multiple 
SELECT *
FROM Etudiant
ORDER BY ville ASC, nom ASC;

Le résultat est d'abord trié par ville, puis par nom à l'intérieur des groupes de même ville.

CHAPITRE 15

Modifier et supprimer les données

15.1 UPDATE

UPDATE permet de modifier les valeurs d'une ou plusieurs lignes.

SQL · UPDATE 
UPDATE Etudiant
SET age = 21
WHERE id = 1;
Explication : UPDATE indique la table à modifier. SET indique la nouvelle valeur. WHERE identifie la ligne concernée.
Sans WHERE, UPDATE peut modifier toutes les lignes de la table. Vérifiez toujours la condition avant d'exécuter la requête.

15.2 Modifier plusieurs colonnes

SQL · Plusieurs modifications 
UPDATE Etudiant
SET age = 22,
    ville = 'Mahdia'
WHERE id = 2;

15.3 DELETE

DELETE permet de supprimer des lignes dans une table.

SQL · DELETE 
DELETE FROM Etudiant
WHERE id = 3;
Sans WHERE, DELETE supprime toutes les lignes de la table. La structure de la table reste présente.

15.4 DELETE, DROP et TRUNCATE

CommandeEffet
DELETESupprime des lignes.
TRUNCATEVide généralement toutes les lignes.
DROPSupprime la table elle-même.
CHAPITRE 16

Les fonctions SQL

16.1 COUNT()

COUNT permet de compter les lignes ou les valeurs non NULL d'une colonne.

SQL · COUNT 
SELECT COUNT(*) AS nombre_etudiants
FROM Etudiant;

16.2 SUM()

SUM calcule la somme des valeurs numériques non NULL.

SQL · SUM 
SELECT SUM(prix) AS total
FROM Produit;

16.3 AVG()

AVG calcule la moyenne des valeurs numériques non NULL.

SQL · AVG 
SELECT AVG(note) AS moyenne
FROM Note;

16.4 MIN() et MAX()

SQL · MIN et MAX 
SELECT
    MIN(prix) AS prix_minimum,
    MAX(prix) AS prix_maximum
FROM Produit;

16.5 Fonctions sur les chaînes

SQL · Fonctions texte 
SELECT UPPER(nom)
FROM Etudiant;

SELECT LOWER(nom)
FROM Etudiant;

SELECT LENGTH(nom)
FROM Etudiant;

UPPER transforme le texte en majuscules, LOWER en minuscules. LENGTH calcule la longueur selon les règles du SGBD et le type de données utilisé.

16.6 Alias avec AS

SQL · AS 
SELECT
    nom AS nom_etudiant,
    age AS age_etudiant
FROM Etudiant;

AS permet de donner un nom plus clair à une colonne dans le résultat.

CHAPITRE 17

GROUP BY et HAVING

17.1 GROUP BY

GROUP BY regroupe les lignes qui possèdent la même valeur pour une ou plusieurs colonnes.

SQL · GROUP BY 
SELECT ville, COUNT(*) AS nombre
FROM Etudiant
GROUP BY ville;
Explication : Les étudiants sont regroupés selon leur ville. COUNT(*) calcule le nombre d'étudiants dans chaque groupe.

17.2 HAVING

HAVING permet de filtrer les groupes obtenus après GROUP BY.

SQL · HAVING 
SELECT ville, COUNT(*) AS nombre
FROM Etudiant
GROUP BY ville
HAVING COUNT(*) >= 3;

Cette requête affiche uniquement les villes qui possèdent au moins trois étudiants.

17.3 Différence entre WHERE et HAVING

WHEREHAVING
Filtre les lignes avant le regroupement. Filtre les groupes après le regroupement.
Utilisé avec les conditions sur les lignes. Souvent utilisé avec les fonctions d'agrégation.

17.4 Exemple combiné

SQL · WHERE + GROUP BY + HAVING 
SELECT ville, AVG(age) AS age_moyen
FROM Etudiant
WHERE age >= 18
GROUP BY ville
HAVING AVG(age) > 20;

La requête sélectionne d'abord les étudiants âgés d'au moins 18 ans, regroupe les résultats par ville, puis conserve les groupes dont l'âge moyen dépasse 20 ans.

CHAPITRE 18

Les jointures SQL (JOIN)

18.1 Pourquoi utiliser une jointure ?

Une jointure permet de récupérer des informations provenant de plusieurs tables en utilisant une condition de relation.

18.2 INNER JOIN

INNER JOIN retourne les lignes qui possèdent une correspondance dans les deux tables.

SQL · INNER JOIN 
SELECT
    Etudiant.nom,
    Classe.nom_classe
FROM Etudiant
INNER JOIN Classe
ON Etudiant.id_classe = Classe.id_classe;
Explication : La table Etudiant est associée à la table Classe. La condition ON compare les identifiants des classes. Seules les lignes ayant une correspondance sont retournées.

18.3 LEFT JOIN

LEFT JOIN retourne toutes les lignes de la table située à gauche, même si aucune correspondance n'existe dans la table de droite. Les colonnes de droite prennent alors la valeur NULL.

SQL · LEFT JOIN 
SELECT
    Etudiant.nom,
    Classe.nom_classe
FROM Etudiant
LEFT JOIN Classe
ON Etudiant.id_classe = Classe.id_classe;

18.4 RIGHT JOIN

RIGHT JOIN retourne toutes les lignes de la table située à droite et les correspondances disponibles dans la table de gauche.

SQL · RIGHT JOIN 
SELECT
    Etudiant.nom,
    Classe.nom_classe
FROM Etudiant
RIGHT JOIN Classe
ON Etudiant.id_classe = Classe.id_classe;

18.5 FULL OUTER JOIN

FULL OUTER JOIN retourne les correspondances ainsi que les lignes sans correspondance des deux côtés.

FULL OUTER JOIN est disponible directement dans PostgreSQL et SQL Server, mais pas dans toutes les versions de MySQL. Dans MySQL, on peut généralement combiner LEFT JOIN et RIGHT JOIN avec UNION.

18.6 CROSS JOIN

CROSS JOIN produit toutes les combinaisons possibles entre les lignes des deux tables.

SQL · CROSS JOIN 
SELECT *
FROM Couleur
CROSS JOIN Taille;

18.7 SELF JOIN

SELF JOIN consiste à joindre une table avec elle-même. Exemple : associer chaque employé à son responsable.

SQL · SELF JOIN 
SELECT
    E.nom AS employe,
    R.nom AS responsable
FROM Employe E
LEFT JOIN Employe R
ON E.id_responsable = R.id_employe;
CHAPITRE 19

Les sous-requêtes SQL

19.1 Définition

Une sous-requête est une requête SQL placée à l'intérieur d'une autre requête.

19.2 Sous-requête avec IN

SQL · Sous-requête IN 
SELECT nom
FROM Etudiant
WHERE id_classe IN (
    SELECT id_classe
    FROM Classe
    WHERE nom_classe = 'TI1'
);

La sous-requête récupère les identifiants des classes nommées TI1. La requête principale sélectionne les étudiants appartenant à ces classes.

19.3 Sous-requête avec AVG

SQL · Comparaison à une moyenne 
SELECT nom, note
FROM Etudiant
WHERE note > (
    SELECT AVG(note)
    FROM Etudiant
);

Cette requête affiche les étudiants ayant une note supérieure à la moyenne générale.

19.4 EXISTS

EXISTS vérifie si une sous-requête retourne au moins une ligne.

SQL · EXISTS 
SELECT *
FROM Etudiant E
WHERE EXISTS (
    SELECT 1
    FROM Inscription I
    WHERE I.etudiant_id = E.id_etudiant
);

La requête affiche les étudiants qui possèdent au moins une inscription.

19.5 ANY et ALL

  • ANY : la comparaison doit être vraie pour au moins une valeur retournée.
  • ALL : la comparaison doit être vraie pour toutes les valeurs retournées.
SQL · ANY et ALL 
SELECT *
FROM Produit
WHERE prix > ANY (
    SELECT prix
    FROM Produit
    WHERE categorie = 'Informatique'
);

SELECT *
FROM Produit
WHERE prix > ALL (
    SELECT prix
    FROM Produit
    WHERE categorie = 'Informatique'
);
CHAPITRE 20

Les vues et les index

20.1 Les vues (VIEW)

Une vue est une requête enregistrée qui se comporte comme une table virtuelle. Elle permet de simplifier certaines consultations et de présenter un ensemble de données précis.

SQL · CREATE VIEW 
CREATE VIEW Etudiants_Mahdia AS
SELECT nom, prenom
FROM Etudiant
WHERE ville = 'Mahdia';

Pour consulter la vue :

SQL · Consulter une vue 
SELECT *
FROM Etudiants_Mahdia;

Pour supprimer la vue :

SQL · DROP VIEW 
DROP VIEW Etudiants_Mahdia;

20.2 Les index

Un index est une structure qui peut accélérer la recherche de certaines données. Il est particulièrement utile sur les colonnes souvent utilisées dans les conditions de recherche ou les jointures.

SQL · CREATE INDEX 
CREATE INDEX idx_etudiant_nom
ON Etudiant(nom);

Pour supprimer un index, la syntaxe dépend du SGBD.

SQL · DROP INDEX (MySQL) 
DROP INDEX idx_etudiant_nom
ON Etudiant;
Les index améliorent certaines lectures, mais occupent de l'espace et peuvent ralentir les opérations d'écriture. Il ne faut pas créer un index sur chaque colonne sans réflexion.
CHAPITRE 21

Les transactions SQL

21.1 Qu'est-ce qu'une transaction ?

Une transaction est un ensemble d'opérations qui doivent être exécutées comme une unité logique.

21.2 Les propriétés ACID

Atomicité

La transaction est entièrement validée ou annulée.

Cohérence

Les règles d'intégrité doivent être respectées.

Isolation

Les transactions concurrentes doivent être gérées correctement.

Durabilité

Les modifications validées doivent être conservées.

21.3 COMMIT

COMMIT valide les modifications réalisées dans une transaction.

21.4 ROLLBACK

ROLLBACK annule les modifications non validées de la transaction.

SQL · Transaction 
START TRANSACTION;

UPDATE Compte
SET solde = solde - 100
WHERE id_compte = 1;

UPDATE Compte
SET solde = solde + 100
WHERE id_compte = 2;

COMMIT;
Explication : Dans cet exemple de transfert, on retire 100 du premier compte et on ajoute 100 au deuxième. COMMIT valide les deux opérations. Dans un véritable système, il faut également vérifier les soldes, les comptes concernés et gérer les erreurs avant la validation.
Les commandes exactes pour démarrer une transaction et certains comportements dépendent du SGBD et du moteur de stockage.
CHAPITRE 22

Sécurité et bonnes pratiques

22.1 Gestion des utilisateurs

Une base de données peut contenir des informations sensibles. Il faut limiter les accès aux utilisateurs qui en ont besoin.

22.2 GRANT

GRANT permet d'accorder des privilèges à un utilisateur. La syntaxe dépend du SGBD.

SQL · Exemple MySQL 
GRANT SELECT
ON universite.*
TO 'lecteur'@'localhost';

Cet exemple accorde le droit de lecture sur les tables de la base universite à un compte MySQL nommé lecteur.

22.3 REVOKE

REVOKE permet de retirer certains privilèges.

SQL · REVOKE 
REVOKE SELECT
ON universite.*
FROM 'lecteur'@'localhost';

22.4 Prévenir les injections SQL

Une injection SQL est une attaque dans laquelle des données saisies par un utilisateur sont interprétées comme une partie de la commande SQL.

Ne construisez pas une requête SQL en concaténant directement des données saisies par un utilisateur.

Utilisez des requêtes préparées avec des paramètres. Exemple avec PHP et PDO :

PHP · Requête préparée 
<?php

$pdo = new PDO(
    "mysql:host=localhost;dbname=universite;charset=utf8mb4",
    "root",
    ""
);

$sql = "SELECT * FROM Etudiant WHERE id = :id";

$stmt = $pdo->prepare($sql);

$stmt->execute([
    "id" => $id
]);

$resultat = $stmt->fetch();

?>
Explication : La requête est préparée séparément des valeurs. Le paramètre :id reçoit sa valeur via execute(). Cette méthode évite d'insérer directement les données utilisateur dans le texte SQL.

22.5 Les sauvegardes

Une sauvegarde permet de restaurer les données après une erreur, une panne ou une suppression accidentelle.

22.6 Bonnes pratiques

  • Choisir des noms de tables et de colonnes clairs.
  • Définir correctement les clés primaires et étrangères.
  • Utiliser les types de données adaptés.
  • Éviter les répétitions inutiles.
  • Vérifier les requêtes UPDATE et DELETE.
  • Utiliser les requêtes préparées dans les applications.
  • Limiter les permissions des utilisateurs.
  • Effectuer régulièrement des sauvegardes.
  • Tester les modifications avant leur mise en production.
CHAPITRE 23

Exemple pratique : construire une base de données universitaire

Nous allons construire progressivement une petite base de données permettant de gérer des étudiants, des classes, des matières et des inscriptions.

Étape 1 : créer la base

SQL · Base universitaire 
CREATE DATABASE IF NOT EXISTS universite;

USE universite;

Étape 2 : créer la table Classe

SQL · Table Classe 
CREATE TABLE Classe (
    id_classe INT PRIMARY KEY AUTO_INCREMENT,
    nom_classe VARCHAR(30) NOT NULL,
    niveau VARCHAR(20)
);

Étape 3 : créer la table Etudiant

SQL · Table Etudiant 
CREATE TABLE Etudiant (
    id_etudiant INT PRIMARY KEY AUTO_INCREMENT,
    nom VARCHAR(50) NOT NULL,
    prenom VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    date_naissance DATE,
    id_classe INT,
    FOREIGN KEY (id_classe)
        REFERENCES Classe(id_classe)
);

Étape 4 : créer la table Matiere

SQL · Table Matiere 
CREATE TABLE Matiere (
    id_matiere INT PRIMARY KEY AUTO_INCREMENT,
    nom_matiere VARCHAR(60) NOT NULL,
    coefficient DECIMAL(4,2) DEFAULT 1
);

Étape 5 : créer la table Inscription

SQL · Table Inscription 
CREATE TABLE Inscription (
    id_etudiant INT,
    id_matiere INT,
    date_inscription DATE,
    PRIMARY KEY (id_etudiant, id_matiere),
    FOREIGN KEY (id_etudiant)
        REFERENCES Etudiant(id_etudiant),
    FOREIGN KEY (id_matiere)
        REFERENCES Matiere(id_matiere)
);

Étape 6 : ajouter des classes

SQL · INSERT 
INSERT INTO Classe (nom_classe, niveau)
VALUES
('TI1', 'Première année'),
('TI2', 'Deuxième année'),
('TI3', 'Troisième année');

Étape 7 : ajouter des étudiants

SQL · INSERT 
INSERT INTO Etudiant
(nom, prenom, email, date_naissance, id_classe)
VALUES
('Ali', 'Mohamed', 'mohamed@example.com', '2006-05-12', 1),
('Ben Salah', 'Amira', 'amira@example.com', '2007-02-20', 1),
('Trabelsi', 'Youssef', 'youssef@example.com', '2005-09-15', 2);

Étape 8 : ajouter les matières

SQL · Matières 
INSERT INTO Matiere
(nom_matiere, coefficient)
VALUES
('Bases de données', 2),
('Programmation', 3),
('Système exploitation', 2);

Étape 9 : inscrire les étudiants

SQL · Inscriptions 
INSERT INTO Inscription
(id_etudiant, id_matiere, date_inscription)
VALUES
(1, 1, '2026-09-15'),
(1, 2, '2026-09-15'),
(2, 1, '2026-09-15'),
(3, 3, '2026-09-15');

Étape 10 : consulter les étudiants et leurs classes

SQL · JOIN 
SELECT
    E.nom,
    E.prenom,
    C.nom_classe
FROM Etudiant E
INNER JOIN Classe C
ON E.id_classe = C.id_classe;

Étape 11 : consulter les matières suivies

SQL · Plusieurs jointures 
SELECT
    E.nom,
    E.prenom,
    M.nom_matiere
FROM Etudiant E
INNER JOIN Inscription I
    ON E.id_etudiant = I.id_etudiant
INNER JOIN Matiere M
    ON I.id_matiere = M.id_matiere;

Étape 12 : compter les étudiants par classe

SQL · GROUP BY 
SELECT
    C.nom_classe,
    COUNT(E.id_etudiant) AS nombre_etudiants
FROM Classe C
LEFT JOIN Etudiant E
    ON C.id_classe = E.id_classe
GROUP BY C.id_classe, C.nom_classe;
Résultat : Vous disposez maintenant d'une structure relationnelle comprenant quatre tables, des clés primaires, des clés étrangères, des données et plusieurs requêtes de consultation.
